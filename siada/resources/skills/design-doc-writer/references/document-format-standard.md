# Design Document Format Standard

This file defines the canonical format for documents generated by the `design-doc-writer` skill.
All sections marked **[REQUIRED]** must appear. Sections marked **[OPTIONAL]** may be omitted if not applicable.

---

## Full Document Template

```markdown
# <Project/Module Name> <Task Type> 设计文档

> 目标：<one sentence — what changes, why>
> 范围：`<primary files/packages in scope>`；不含：`<explicitly out-of-scope items>`

---

## 目录  [REQUIRED]

- [1. <Chapter Title>](#...)
  - [1.1 <Section Title>](#...)
    - [1.1.1 <Sub-section Title>](#...)
- [2. <Chapter Title>](#...)
  - [2.1 <Section Title>](#...)
  - ...
- ...
- [N. 实施步骤](#...)
  - [N.1 Step 1：<Step Title>](#...)
  - [N.2 Step 2：<Step Title>](#...)
  - ...

---

## 1. <Chapter Title>

<Content is entirely task-specific. Other chapters (1 through N-1) have no fixed structure — author them based on what best communicates the design for this task.>

### 1.1 <Section Title>

<Content.>

#### 1.1.1 <Sub-section Title>

<Content.>

---

## N. 实施步骤  [REQUIRED — always the last chapter]

> Steps are in dependency order. Steps marked **（可独立提前执行）** have no dependencies on other steps in this plan.

### N.1 Step 1：<Step Title>（对应 <analysis section ref>）

**目的：** <One sentence — why this step exists.>

**当前状态：** `待执行`

**改动清单：**

1. `path/to/File.java`
   - <Specific change: delete method X; add field Y of type Z; rename parameter>
   - <If adding code, show the full signature or key snippet>

2. `path/to/Another.java`
   - ...

**验收标准：**
- [ ] <Concrete, observable criterion — file exists / method deleted / test passes / output format matches>
- [ ] <Each item in the change list has at least one corresponding criterion>
- [ ] 所有现有测试通过
```

---

## Status Values

Use exactly these values for `**当前状态：**`:

| Value | Meaning |
|---|---|
| `待执行` | Not started |
| `进行中` | Work has begun, not complete |
| `已完成` | All acceptance criteria met |
| `已跳过` | Deliberately skipped (with reason noted) |
