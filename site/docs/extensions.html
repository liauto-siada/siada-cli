Skills、Agent 与插件

把你熟悉的工作方法交给 Siada：用规则保留约定，用 Skill 复用流程，用子 Agent 分工，再通过插件和 MCP 接入需要的工具。

选一种适合的扩展方式

方式适合什么
项目规则始终适用的约定，如测试命令、代码风格和项目背景。
Skill按需读取的一套标准流程，可带参考资料与工具脚本。
自定义命令用简短斜杠命令调用重复使用的提示词。
命名子 Agent交给专门角色独立处理的任务，例如调研或代码审查。
MCP外部工具或数据服务，如数据库、浏览器与文档系统。
插件与 Hooks成套安装技能、工具与会话事件脚本。

让项目约定进入上下文

在项目根目录放置 SIADA.md 或 AGENTS.md，写明代码风格、测试命令和需要遵守的边界。/init 可以分析当前项目并生成 SIADA.md；修改指令文件后，使用 /context-file-refresh 刷新。

交互输入
/init
/context-file-refresh

个人通用约定可以写在 ~/.siada-cli/siada_rule.md，项目或目录级约定写在对应目录的 siada_rule.md。用 /rule-list 看加载了哪些规则，/rule-show 看合并内容，修改后用 /rule-refresh 刷新。

把重复流程写成 Skill

在项目的 .siada-cli/skills/ 下给每个 Skill 建一个目录，目录中放 SKILL.md。文件开头的 name 与 description 告诉 Siada 何时使用它，正文写具体流程。

.siada-cli/skills/review-checklist/SKILL.md
---
name: review-checklist
description: 当需要检查代码改动的测试覆盖和风险时使用。
---

先阅读本次改动，再检查相关测试。
按文件列出问题、原因和建议；没有发现时说明检查范围。

输入 /skill-list 查看可用技能，/skill-reload 重新加载。直接输入 /review-checklist 检查这次改动 即可调用，也可以在自然语言里指定使用它。

个人通用技能放在 ~/.siada-cli/skills/；兼容读取 .agents/skills/ 和 .claude/skills/。同名技能以 name 区分，个人技能优先于项目技能和内置技能；同一层级的 .siada-cli/skills/ 优先于兼容目录。

不想手写文件，可以直接说“用 skill-creator 把这套检查流程做成 Skill”。在脚本模式中，把技能名称写入提示文本，例如 siada-cli -p "使用 review-checklist 检查这次改动"。

用短命令保存常用提示词

自定义命令使用 TOML 文件。个人命令放在 ~/.siada-cli/commands/，项目命令放在 .siada-cli/commands/；子目录会变成命令名中的冒号。

.siada-cli/commands/git/review.toml
description = "检查已暂存的改动"
prompt = """
审查下面的 Git diff，报告缺陷与测试遗漏。
补充要求：{{args}}
!{git diff --staged}
"""

在会话中输入 /git:review 重点检查边界条件。{{args}} 接收命令参数，@{文件路径} 嵌入文件内容，!{Shell 命令} 在本机执行并嵌入输出。

给专门任务定义命名子 Agent

在 .agents/agents/ 中创建 Markdown 文件。name 与 description 是必填字段；正文描述这个 Agent 的职责和交付格式。主 Agent 会根据任务描述通过 run_subtask 派发任务。

.agents/agents/reviewer.md
---
name: reviewer
description: 实现完成后，审查改动中的缺陷与测试遗漏。
---

阅读本次改动和相关测试。
只报告可复现的问题，并给出文件位置与修复建议。

在会话里说“让 reviewer 审查这次改动”即可。个人角色放在 ~/.siada-cli/agents/，定义会在下一轮读取。任务可并行分工，也可交给后台子 Agent 后继续主任务。

可选字段用途
tools限定可用工具。
skills预载指定技能。
mcpServers给该 Agent 接入 MCP 服务。
background设为 true 时在后台执行。
effort指定推理强度。
model指定独立模型；inherit 沿用默认选择。

sub_agent.enabled 控制是否允许派发，sub_agent.llm_config 可统一设置子 Agent 模型。需要更多字段说明时，可以问 /siada-help 如何定义命名子 Agent。

tools 使用实际工具名；全部名称都无法匹配时会沿用默认工具集。它用于配置角色能力，文件与命令的实际访问仍由系统权限决定。

从插件市场添加能力

输入 /plugin 打开插件管理，浏览市场并安装需要的技能或插件。插件可以一起提供 Skills、MCP 服务器和 Hooks。

交互输入 · 常用管理操作
/plugin
/plugin marketplace add anthropics/claude-code
/plugin disable PLUGIN_NAME
/plugin enable PLUGIN_NAME
/plugin validate PLUGIN_NAME

把 PLUGIN_NAME 换成已安装插件的名称。安装或更新后，按界面提示重新加载相应能力；技能可用 /skill-reload 刷新。

在关键步骤加入 Hooks

Hook 在用户提交消息、工具执行前后、会话结束或出错等节点运行脚本。可以用它记录审计信息、提供上下文，或在工具执行前检查条件。

常用事件触发时机
UserPromptSubmit用户提交消息后、Agent 处理前。
PreToolUse工具执行前，可检查或阻止调用。
PostToolUse工具执行后，可处理输出或补充上下文。
StopAgent 停止回复时。
OnError会话发生异常时。

Siada 支持 Claude Code 格式的插件 Hooks。可以通过插件市场安装 hookify，然后按该插件的说明创建和查看规则；插件自己的命令会在安装后出现。

用 MCP 接入外部工具

个人服务器配置放在 ~/.siada-cli/mcp_config.json；项目可使用根目录的 siada_mcp_config.json。在 mcpServers 中登记服务，项目中的同名服务会覆盖个人配置。

mcp_config.json · 将命令换成你的 MCP 服务程序
{
  "mcpServers": {
    "my-tools": {
      "type": "stdio",
      "command": "my-mcp-server",
      "args": []
    }
  }
}

连接后用 /mcp-server 检查服务状态，/mcp-list 查看它提供的工具。服务器自身的启动命令、权限与凭据需要按该服务的文档配置。
