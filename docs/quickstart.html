开始使用

从一个项目目录开始你的第一段对话。交互模式适合连续协作；脚本模式适合把一个明确任务交给 Siada 执行。

在项目目录启动

在终端进入你的项目，然后运行 siada-cli。工作目录决定它首先看到哪个项目，也决定会话恢复时使用的工作区。

TERMINAL · 将 my-project 换成你的项目目录
cd my-project
siada-cli

第一次启动时，按界面提示选择登录方式或配置模型服务。之后直接输入任务；在同一段会话中可以继续追问、修改文件和运行检查。

已有账号或服务配置需要调整时，在交互界面输入 /configure。模型选择与自备 API Key 的设置见 模型与配置。

写清目标和验收方式

把目标、范围和完成标准写在同一条消息里，便于 Siada 在执行后核对结果。

对话输入示例
找出登录页测试失败的原因，只修改相关代码。
修复后运行对应的测试，并说明测试结果。

如果任务还缺少路径或复现步骤，继续在会话里补充即可；对话会保留前面的上下文。

执行一次性任务

使用 --prompt 或 -p 传入任务，Siada 进入非交互模式，执行后退出。可以组合模型等启动参数，适合脚本或 CI 中的单次检查与生成任务。

TERMINAL
siada-cli --prompt "梳理这个项目的测试入口，并列出需要关注的测试"
siada-cli --model MODEL_ID -p "创建一个 REST API 端点并运行相关测试"
继续上一段工作

需要继续指定会话时，组合 --resume SESSION_ID 与 --prompt。不带 ID 的 --resume 在非交互模式下恢复当前项目最近的一段会话。用法见 会话恢复。

引用文件和目录

在对话中输入 @ 加文件名或目录，让 Siada 把相应内容带入当前任务。路径以当前项目为基准；文件名也支持模糊匹配。

对话输入示例
@src/auth.py 解释这个文件里的登录校验流程
@tests/ 看看与登录相关的测试覆盖了哪些场景

把截图带进对话

复制图片后，在 Siada 输入框按 Ctrl+V，或在 macOS 上按 Cmd+V 粘贴截图，并说明希望它检查的内容，例如“根据这张报错截图定位问题”。主模型支持图片时可直接理解；也可配置视觉模型辅助读取，见 图片与视觉模型。

Linux 剪贴板需要相应系统工具：Wayland 使用 wl-clipboard，X11 使用 xclip。发送、换行和中断的快捷键见 输入与快捷键。

接下来读什么

输入 /help 查看当前可用命令；需要切换模型可用 /model；任务跨多轮时可用 /resume 找回已有会话。各自的用法见 命令参考 与 会话管理。
