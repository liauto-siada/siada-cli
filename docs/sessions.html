04 / CONTEXT

会话、上下文与记忆

接着上次的工作，为长任务保留清楚的目标，再把持续适用的习惯和项目约定留给下一次协作。

恢复已有会话

在交互界面输入 /resume，浏览当前项目的会话并选择一条继续。也可以在终端传入会话 ID，直接恢复指定对话。

TERMINAL · 将 SESSION_ID 换成会话 ID
siada-cli --resume SESSION_ID
siada-cli --resume SESSION_ID --prompt "继续运行相关测试并说明结果"

不带 ID 的 siada-cli --resume 在交互模式下打开会话浏览器；与 --prompt 组合时恢复当前项目最近的会话。恢复时先进入原项目目录，跨工作区恢复会提示目录不匹配。可用 /status 查看当前会话 ID。

开启新任务或压缩历史

/clear 开始一段新的会话，适合换到无关任务；之前的会话仍可通过恢复入口找回。/compact 则压缩当前对话历史，保留继续工作的摘要。对话太短或已经压缩时，它可能提示无需处理。

交互输入
/clear
/compact

/clear 不会撤销项目文件的修改。如果只是临时询问一个旁支问题，使用 /btw 问题，回答不会写入主对话历史。

比较与恢复文件检查点

需要记录任务中的文件变化时，在交互启动时传入 --checkpointing。未显式开启时，检查点默认关闭；非交互 --prompt 模式不启用检查点。

TERMINAL
siada-cli --checkpointing
命令用途
/compare 检查点文件查看工作目录与指定检查点的差异。
/undo 检查点文件撤销该检查点中的修改，恢复到修改前的状态。
/restore 检查点文件恢复指定检查点保存的状态。

这些命令需要提供已经生成的检查点文件名；不带文件名时会提示用法。先比较差异，再选择要恢复的状态。长期默认值可在 checkpoint_config.enable 和 checkpoint_config.max_checkpoint_files 中设置。

让任务保持一个明确目标

对于需要多轮推进的工作，/goal 目标 会把目标交给 Agent 执行，并在每轮之后由验证器判断是否完成。验证器没有可执行的下一步、连续失败达到上限或遇到系统错误时，自动续跑会停止。

交互输入示例
/goal 修复登录测试并通过相关测试
/goal clear

新输入 /goal 目标 会替换旧目标，无需先清除。完成由验证器判断，没有 /goal complete 命令；用 /goal clear 移除当前目标。

goal.max_turns 控制连续验证失败后自动停止的上限，默认 6。目标因连续失败停下后，发送新的自然语言消息可以补充信息并继续推进。把测试、文件格式或页面最终状态写进目标，便于核验。

给项目提供持续的上下文

项目中的 SIADA.md 或 AGENTS.md 可写入长期适用的约定。/init 会分析项目并生成 SIADA.md；已有指令可通过 /context-file-refresh 刷新。项目规则与 Skills 的区别见 扩展能力。

让习惯与经验延续到下一次

记忆保存个人工作偏好、项目经验与适用的事实。相关文件位于 ~/.siada-cli/workspace/memory/；个人偏好记录在 USER.md，经验与事实记录在 MEMORY.md。

交互输入 · 查看或调整记忆开关
/memory
/memory enable
/memory disable

你可以明确说“记住：这个项目使用 npm，交付前运行现有测试”。memory.enabled 是总开关；个人偏好、事实记忆与结构化记忆的细分设置见 运行设置。

控制任务需要读取的文件

在工作区根目录创建 .siadaignore，使用类似 .gitignore 的模式，让内置文件工具忽略指定路径。生成目录、大文件和不需要进入任务的内容都可以写在这里。

.siadaignore · 示例
.env
.env.*
node_modules/
dist/
*.log

这用于文件读取与修改范围控制；直接运行的 Shell 命令仍按系统权限执行。

导出或分享这段工作

在终端 UI 中输入 /export 导出文本，或用 /export session-notes.txt 指定文件名。需要在浏览器继续协作时，使用 /share 生成会话链接，前提与用法见 会话分享。
