# 浏览器学习重试

浏览器执行后的学习由后台 worker 处理，任务保存在 SQLite 队列中。
每个证据分块需要一次反思请求；提取到有效经验后，可能再发起一次整理请求。
这些请求使用 fast model。

HTTP 401/403 鉴权或权限错误会暂停对应执行记录（`status=paused`）。
普通失败采用指数退避，累计最多允许三次失败的处理尝试，然后保留为
`status=failed`。两种状态都保留执行记录和 `last_error`，进程重启后也不会
自动重试。修正凭据不会自动恢复已暂停的记录。取消任务只释放租约，
不消耗失败次数。

学习请求关闭 SDK 内部重试，由持久化队列负责重试。
三次上限针对处理尝试，并非 HTTP 请求数：包含多个证据分块的记录，
每次处理可能发起多个请求。

worker 每五秒检查一次，但只有记录当前可领取且没有其他消费者持有有效的
全库租约时才处理队列。等待退避、暂停以及正在处理的记录不会触发空处理。
空处理日志降为 DEBUG；实际处理成功或失败的批次仍保留 INFO 日志。
