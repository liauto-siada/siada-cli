# Chrome ACP 交互网页

Chrome ACP 可以在浏览器侧边栏和网页聊天中展示可操作的 HTML 界面。例如：
“生成一个经营看板，可以切换时间范围、调整预算。”控件会即时更新页面；
用户点击“继续分析”等按钮时，页面标识和当前状态会一起送回同一段对话。

点击页面标题旁的 **Share**，或直接告诉助手“把这个界面分享成局域网网页”。
Share 会发布当前页面和操作状态，返回局域网链接，并提供 **复制链接** 和
**打开网页**。接收者可以独立操作，后续状态分别保存在各自浏览器中。
需要助手继续处理时，回到 Siada 对话。

分享网页保存在 `~/.chrome-acp/pages/shared/`。Chrome ACP 运行时，局域网内可通过
链接访问；代理重新启动并使用相同目录及局域网地址后，链接仍可使用。
分享会启动一个监听所有网卡的只读 HTTP 服务，通常使用 9316 端口（代理端口加一）。
如需修改端口，启动代理前设置 `SIADA_UI_SHARE_PORT`。该服务仅提供已发布网页，
代理继续使用原有连接配置。局域网内获得随机分享链接的人可以读取页面快照。
之后在聊天中修改界面，不会改变已经分享的页面。

助手通过浏览器 MCP 服务发现 `browser_present_ui`、`browser_share_ui` 和
`browser_list_ui`。页面使用自包含 HTML、内联 CSS/JavaScript，以及
`window.siadaUI.state`、`setState(patch)` 和 `submit(prompt)` 管理状态和
提交操作。生成页面内部禁止外部资源和网络请求。源码上限为 2 MiB，
状态上限为 64 KiB。聊天中的状态变化会保存到本地代理；保存失败会显示重试提示。

如需自定义保存目录，在启动代理前设置 `SIADA_UI_DIR`。

可以这样提问：“展示四冲程发动机的工作过程，可以隔离气缸并打开剖面。”
模型自主决定使用普通 HTML，还是内置的
[teardown 工具包](https://github.com/elvarofficial/teardown)。界面保持统一入口，
两种制作方式都使用同一个 Share。

源码工程通过 `browser_ui_project` 创建，使用 `browser_ui_build` 构建，
再用 `browser_ui_inspect` 检查侧边栏或桌面宽度下的画面和运行诊断。
工程保存在页面目录的 `projects/` 下，重启后仍可修改。构建更新同一张卡片，
保留已经提交的操作状态；失败时保留上一个可用网页。创建或构建成功后，
优先在当前聊天中直接展示。检查是模型按需选择的诊断能力，不是展示前置步骤，
也不要求打开独立页面。模型决定是否继续细化，并复用已有结果，避免重复检查。

网页所需的 teardown 工具包、指南及三种机构的示例源码随 Chrome ACP 安装，
并保留原始 MIT 许可证，无需另外安装 skill。默认使用随包源码；如需明确
改用自定义上游工程，可在启动代理前设置 `SIADA_TEARDOWN_DIR`。
`teardown-v8` 示例提供可读的视角、剖切、隔离、转速、曲轴角度和分层拆解控件；
`teardown` 工程提供工具包、指南和示例源码，供模型制作其他机构。
画面检查需要安装 Chromium；自动查找失败时设置 `SIADA_UI_CHROMIUM`。

实时模拟器使用 `siadaUI.registerState({capture, restore})`，在 Share 或提交
助手操作时读取最新的少量 JSON 状态。`siadaUI.onVisibility(callback)` 可在
界面移出视口时暂停渲染。状态保存应围绕用户操作和检查点，避免逐帧写入代理。

顶部的 **显示** 按钮可以调节界面缩放（80%–120%）和输入框行数（1–6 行）。
缩放会同时改变字号、间距和内嵌交互网页的大小。默认使用 90% 缩放和 1 行
输入框；长消息在输入框内部滚动。点击 **恢复默认** 可重置两项设置。
关闭并重新打开侧边栏后，设置会保留。网页客户端也支持这些控件，设置分别保存。
